# Deployment Guide

## Prerequisites

- Terraform >= 1.6.0
- AWS CLI v2 configured with credentials allowed to provision this stack
- AWS account
- Docker Hub repositories containing:
  - `cloudwithnitesh/nexops-backend:1.0.0`
  - `cloudwithnitesh/nexops-frontend:1.0.0`
- Optional: a domain registered at GoDaddy

## 1. Bootstrap the remote Terraform state backend

Run once per AWS account:

```bash
cd bootstrap/state-backend
terraform init
terraform validate
terraform plan
terraform apply
```

Record:

```bash
terraform output state_bucket_name
terraform output dynamodb_table_name
```

The S3 bucket is encrypted/versioned and the DynamoDB table provides Terraform state locking.

## 2. Initialize the main environment with the remote backend

From `environments/dev`:

```bash
terraform init -backend-config="bucket=<STATE_BUCKET_NAME>"
```

Example:

```bash
terraform init -backend-config="bucket=nexops-terraform-state-123456789012"
```

Do not commit the real bucket name if your repository policy treats account-specific infrastructure details as private.

## 3. Configure application and AWS variables

```bash
cp terraform.tfvars.example terraform.tfvars
```

Set:

```hcl
alert_email    = "you@example.com"
db_name        = "nexops"
db_username    = "nexopsadmin"

backend_image  = "cloudwithnitesh/nexops-backend:1.0.0"
frontend_image = "cloudwithnitesh/nexops-frontend:1.0.0"
```

The RDS password and JWT signing secret are generated by Terraform and stored in AWS Secrets Manager. Do not add a database password to `terraform.tfvars`.

## 4. Optional: enable a GoDaddy domain with Route 53 + ACM

If your purchased domain is `nitesh.shop`:

```hcl
route53_zone_name = "nitesh.shop"
domain_name       = "nitesh.shop"
```

Create only the Route 53 hosted zone first:

```bash
terraform apply -target=module.route53.aws_route53_zone.this[0]
terraform output route53_name_servers
```

At GoDaddy, replace the domain's nameservers with the Route 53 nameservers returned by Terraform.

After DNS delegation is active, run:

```bash
terraform apply
```

Terraform then creates the ACM DNS validation record, waits for certificate validation, attaches HTTPS to the ALB, and creates the ALB alias record.

Finally:

```bash
terraform output application_url
```

Expected form:

```text
https://nitesh.shop
```

If the domain is not purchased yet, leave:

```hcl
route53_zone_name = ""
domain_name       = ""
```

The stack will still work through:

```bash
terraform output alb_dns_name
```

## 5. Validate and deploy

```bash
terraform fmt -recursive
terraform validate
terraform plan
terraform apply
```

Confirm the SNS subscription email.

## 6. Verify the application

Check:

```bash
terraform output alb_dns_name
terraform output application_url
terraform output autoscaling_group_name
terraform output database_secret_name
```

Then in AWS verify:

1. ALB is active.
2. Target group has two healthy targets.
3. ASG has the desired instances.
4. RDS is available.
5. EC2 instances appear in Systems Manager.
6. `https://<your-domain>` works when DNS/ACM are enabled.
7. Login/API requests succeed.
8. `/api/health` returns a successful response.
9. CloudWatch alarms and SNS subscription are configured.

## 7. Troubleshooting instance bootstrap

Use Systems Manager Session Manager rather than SSH.

Useful commands:

```bash
sudo cat /var/log/nexops-bootstrap.log
sudo docker ps
sudo docker logs nexops-backend
sudo docker logs nexops-frontend
sudo nginx -t
curl -fsS http://127.0.0.1:8000/api/health
```

## 8. Tear down

```bash
terraform destroy
```

The remote state backend is intentionally separate and protected. Do not destroy it unless you are decommissioning the entire Terraform environment.

## Important cost note

This architecture uses RDS, NAT Gateway, EC2, ALB, and other billable AWS resources. Destroy the environment when you are not actively using it.
